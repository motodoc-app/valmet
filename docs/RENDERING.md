# Rendering the scan: what changed, numbers, and what is feasible

The supplied file `equipment_room.ply` **is a trained 3D Gaussian Splatting model** (header "Generated by EGS",
1,676,481 splats, 59 float properties: position, log-scale, quaternion (`rot_0` = w, stored last), opacity logit,
DC colour and 45 `f_rest` coefficients = spherical harmonics degree 3; all records valid). There are no source photos
or camera poses. "Better Gaussian splatting" here therefore means **rendering this model more faithfully and
presenting it more cleanly**, not re-training it.

## 1. Diagnosis (measured, same camera poses)

Stills come from `?capture` mode (nothing renders unless `window.__step()` is called), 1280×720, pixel ratio 1,
Chromium + SwiftShader (software GL). Poses: home view, eye level towards P-005 at (2.42, 0.5, 3.07), high overview,
Broadcast and Top camera poses (robot at its start).

| Suspect | Measurement | Verdict |
|---|---|---|
| ACES tone mapping on display-referred splat colours | Spark's splat shader has no `tonemapping_fragment`; renders with ACES vs none differ by 0.03–0.13 / 255 (mean abs, only the overlay lines) | **Not a cause.** ACES never touched the splats. |
| 511,400 low-opacity splats dropped (opacity ≤ 0.06, 30.5 % of the model) | They carry 4.2 % of the opacity-weighted footprint; restoring them fills a little, softens speckle slightly | **Minor.** Visible only as slightly smoother walls/floor. |
| SH dropped | SPZ keeps SH; after its quantisation 31–46 % of band-1 and 9–18 % of band-2/3 coefficients are non-zero; effect = subtle view-dependent sheen | **Minor.** |
| Colour clipping in `.splat` (27 % of DC channels outside 0..1) | Spark's packed format clips to 0..1 on load for every path | **Unchanged** (would need a custom Spark encoding; not worth the risk now). |
| Spark anti-alias blur (`blurAmount` 0.3) vs classic 3DGS pre-blur | 1.1–1.3 / 255 mean difference | **Not a cause.** Defaults kept. |
| **Floaters and wall skins outside the room** | In the overview / Broadcast / Top views they form a thick blurry rim around the room (see images) | **Main cause** of the "unfinished" look from high cameras. |
| **Home camera 20 cm under the ceiling ducts** (y 1.85 m, ceiling 2.05 m) behind the insulated pipe column | Blurry duct splats fill the top third of the first picture | **Main cause** of a poor first impression. |
| **Wireframe clutter** (every asset as a bright box, 0.85 alpha) | 30 coloured boxes over the photo | **Contributes** to the "not clean" look. |

Honest summary: the classic export already looked photoreal at eye level; full fidelity is a real but modest gain.
The big visible wins are presentation: what is shown from high cameras, where the first camera stands, and how much
geometry is drawn over the photo.

## 2. What changed

**Full-fidelity scan path (default).** `web/scripts/build-hq-scan.mjs` (Node, uses Spark's own `transcodeSpz`, ~10 s)
reads the PLY by property name and writes `web/public/static/hq/scan-hq.json` + 18 SPZ chunks (gzip):

* every splat with opacity ≥ 1/255: **1,669,970** splats (only 6,511 never-visible ones dropped), **SH degree 3**;
* splats stay in the scan's own frame; the canonical transform (`data/processed/integrity_report.json`, the same one
  `scene.json` uses) is the mesh matrix, so SH rotate correctly and everything lines up with picking, the occupancy
  grid and the semantic boxes (verified in `tests/e2e-render.mjs`);
* chunks = 3 importance tiers × {below, above the 1.7 m cut-away} × {clean, haze, outside-the-walls}, so cut-away and
  clean-scan stay instant visibility flips; phones (LITE) load tier 0 only (730,000 splats, 15.6 MB);
* the raw PLY is not in git, so the chunks are committed (37.0 MB, largest file 7.7 MB < the 15 MB host limit).
  `npm run build` verifies them (`check-manifest.mjs`: existence, size, sha256, gzip magic, tier 0 present, and now
  also that no file under `static/` or `data/` exceeds 15 MB, except the legacy `data/scene.splat`).

**Fallback chain** (`api.js` `scanManifest`, `Facility.loadScan`): SPZ chunks → if the manifest is missing, the first
chunk fails to download/decode, or the splat engine is unavailable → the classic xq16 chunks → `data/scene.splat`.
`?render=classic` forces the classic path. Later SPZ chunks that fail are skipped (the room is already shown).

**Cleaner presentation.**
* `scanfilter.js` gains a third class, "outside": splats > 6 cm beyond a fitted wall plane (the wall skin and what lies
  behind it). It was hidden in cut-away views (Broadcast/Top/overview), together with the haze; at eye level the
  walls stay (Clean scan still hides only the haze). *Superseded in Round 3 (§7): hiding it removed the walls; they
  now always stay.* Same classifier at build time (SPZ) and at load time (classic).
* `homeView`: eye height 1.65 m at the short wall nearest the robot, looking down the long axis of the room.
* Asset condition pins (`twin.js`): a small constant-size pin above each asset that is not healthy (13 of 30), colour =
  condition; asset frames are now faint (0.45 alpha). Pins step aside in the semantic view and when the asset's own
  label is up. Hover / selection outlines are unchanged.
* **Twin** rail toggle (`layers.js`, cube icon): drivable-floor tint from the occupancy grid + 0.5 m floor grid, room
  outline from the fitted wall planes (floor junction, top, corners), asset outlines in condition colour.
* `semantic.js` families now use the same label → family mapping as `scripts/scene_quality.py` (`FAMILY`), so legend,
  site map, floor plan and quality panel show identical counts (Rotating 33, Electrical 45, Piping 239, Unidentified 260).

## 3. Numbers

| | Classic (before) | Full fidelity (after) |
|---|---|---|
| Splats rendered | 1,164,997 | 1,669,970 (+43 %) |
| SH | none (DC only) | degree 3 (SPZ-quantised) |
| Download | 19.8 MB (3 xq16 chunks) | 37.0 MB (18 SPZ chunks, max 7.7 MB); phones 15.6 MB |
| First splats on screen* | 2.9 s | 2.2–3.2 s |
| All chunks shown* | 3.2–3.5 s | 2.9–4.4 s |
| Frame time, software GL, 1280×720** | home 29.5 s · eye 18.5 s · overview 17 s | home 29.6 s · eye 23 s · overview 23 s |

\* local `vite preview` on a shared 4-core box (network time ≈ 0). On a real connection the download dominates:
37 MB ≈ 6 s at 50 Mbit/s; the first chunk (7.7 MB) shows the recognisable room after ≈ 1.3 s.
\** SwiftShader on a CPU, measured with a `readPixels` after `__step()`; real GPUs are 2–3 orders of magnitude faster.
The relevant ratio is ≈ 1.25–1.35× the classic cost, i.e. it scales with splat count.

GPU memory (estimate): ≈ 16 B/splat packed + ≈ 40 B/splat SH → ≈ 95 MB for the full set, ≈ 40 MB for phones.

## 5. Feasibility (honest)

| Option | Feasible? | Notes |
|---|---|---|
| Render the supplied 3DGS faithfully (all splats, SH, correct frame) | **Done** | This branch. Remaining fidelity gaps: Spark's 0..1 colour clip; SPZ SH quantisation. |
| Re-train / fine-tune the 3DGS (denoise floaters, sharpen) | **No** | Needs the source images and camera poses; we have neither. A pilot with the original capture data could re-train with floater regularisation and anti-aliasing (hours of GPU time). |
| Gaussian object extraction (per-asset splat sets, movable splats) | Pilot | Needs CUDA tooling (e.g. Gaussian Grouping / SAGA style) and, for good masks, the source views. A rough version is possible by cutting splats with our OBBs (no training), but edges would be ragged; not before the deadline. |
| Mesh reconstruction (Poisson / TSDF) | Pilot | From splat centres: Poisson on ≈ 1 M oriented points (normals from the thinnest splat axis) takes minutes on a CPU, but gives lumpy, blobby surfaces with holes under equipment and colour bleeding; good enough for a collision / navigation proxy, not as the photoreal layer. From rendered depth: TSDF fusion of depth maps rendered from the splats at many poses (needs a depth render pass and pose planning; ~1 day) gives cleaner planar walls/floor but thin pipes and cables vanish. Risk is high for a demo; the splats already look better than such a mesh. |
| Clean geometry layer (planes, OBBs, occupancy) | **Done / in use** | Fitted planes, 676 OBBs and the occupancy grid drive picking, navigation, Plan mode and the Twin overlay. |

Recommendation: before the deadline, ship the full-fidelity scan with the cleaned high views, pins and Twin toggle
(this branch). In a pilot: obtain the capture images to re-train with floater suppression, and build per-asset splat
segments for "move the real pump" planning.

## 7. Round 3 (final QA): the "cut-outs" in Top and Angled

Same method: `?capture`, 1440×900, pixel ratio 1, full-fidelity scan (18 SPZ chunks, 1,669,970 splats), identical
camera poses before / after (`docs/rendering/r3-*.jpg`, left = before, right = after).

**Root cause (measured, mechanisms toggled one at a time at the Top and Angled poses).** The cut-away hid whole scan
layers. (1) It dropped the "outside" layer: splats more than 6 cm behind a fitted wall plane. Real walls are not flat
(pipes, cabinets, plaster), so about half of every wall's splats lie 6–30 cm behind its plane (per wall: 31–49 k
splats within ±6 cm, 22–64 k at 6–30 cm). Hiding them took the walls out of the room: Angled showed the room as an
island in a black void, Top had ragged, wedge-shaped edges (the +z plane is tilted 5.5°). Showing that layer alone
brings the back wall, its windows and cabinets back. (2) Everything above exactly 1.7 m was sliced off (whole
chunks), so tall equipment and walls ended in a hard cut. Not causes: the haze filter (≈ 0.2 % of the opacity in
the open floor area; showing it only adds a whitish fog), near/far planes (0.03 / 120 m), Spark sorting (shots are
taken after the sorter is idle), the LOD tier (desktop loads all 18 chunks), the floor plate (it only shows through
real gaps).

**What is genuinely missing in the scan (not fixed, not painted over).** The ceiling and overhead duct band (1.8–2.1 m)
were captured from below: seen from above they are a blurry sheet that hides the room (see the "Show full scan"
image). The open middle of the floor is thinly reconstructed (dark speckle between splats from high up). The tops of
tall objects and wall tops are smeared from directly above. These gaps stay dark; the cut-away chip says
"dark gaps = no scan data".

**Changes.**

| Change | Where | Evidence |
|---|---|---|
| Soft ceiling cut instead of layer slicing: one Spark `SplatEdit` (horizontal plane SDF, opacity × 0, soft edge) fades out everything between 1.55 and 1.85 m; walls ("outside" layer) and the upper layer stay; haze stays hidden. Render-time only, applied in world space after the mesh transform, so it works for SPZ and classic splats. The point-cloud fallback (no splat engine) keeps the 1.7 m layer cut. | `facility.js` (`_applyCut`, `_layerOn`, `cutY`) | `r3-top.jpg`, `r3-angled.jpg`, `r3-plan.jpg`; `e2e-render`: "soft ceiling cut … walls and tall equipment kept" |
| Cut-away chip in every overhead view (Top, Angled, overview, Plan Top/Angled): says what is hidden and that dark gaps are missing data; one tap "Show full scan" / "Cut-away". The choice survives camera switches (Top → Angled → Chase → Top) until undone. | `layers.js`, `layers.css`, `Facility.setCutUser` | `r3-top-cut-vs-full.jpg`; `e2e-render`: three "Cut-away chip" checks |
| Chase camera is pulled inside the fitted walls (margin 0.3 m). Before, it stood behind a wall in 541 of 1,028 route frames (5 routes), up to 1.5 m, looking at the back of the wall. After: 0 frames. | `main.js` `keepInRoom` | `r3-chase-near-wall.jpg`; `e2e-pov-xray`: "Chase: never behind a wall" |
| Angled camera keeps its 45° broadcast pose but swings up (same distance, up to 78°) when the robot comes close to the wall it looks across, so the kept wall never hides the robot: frames with the robot behind that wall 165 → 23 of 1,028 (the rest is the camera's damped follow lag). | `main.js` `broadcastOffset(p)` | `r3-angled-arrival.jpg`; `e2e-pov-xray`: "Angled: the near wall hides the robot in < 5 %" |
| Twin drivable-floor tint 70 → 38 / 255: the scanned floor reads through it in Plan. | `twin.js` | `r3-plan.jpg` |

Camera audit (`?scan=off`, logic only): every mode switched mid-route (POV → Chase → Angled → Top → Free → POV →
Angled → Chase) leaves the route object, progress (monotonic) and motion untouched; no NaN; dock and navpad light the
active mode; POV stays ≥ 0.79 m inside the walls except when the robot hugs a wall (≤ 0.17 m into the fitted plane,
inside the wall's own splat thickness).

Cost: overhead views now draw 1,552,575 splats (everything except the haze) instead of 965,663, i.e. the same set as
eye level, so the overhead frame cost is bounded by the eye-level cost that already ran; splats faded to zero opacity
are not drawn. Draw calls 20–30, adaptive pixel ratio unchanged (desktop 1–2, phones 1).

**Data check.** `data/raw/equipment_room.ply` re-hashed: SHA-256 `83d8c7d9…2f955`, 395,651,019 bytes, header
"Generated by EGS", 1,676,481 splats, 59 float properties (x y z, scale_0..2, rot_1..3 + rot_0, f_dc_0..2, opacity,
f_rest_0..44). Decoding all 18 SPZ chunks (SPZ v3, SH degree 3, 12 fractional bits) gives 1,669,970 splats = the
PLY minus its 6,511 splats with opacity < 1/255. A sample of 7,192 splats matched to the PLY by position: position
error ≤ 0.1 mm, opacity ≤ 0.002, log-scale ≤ 0.033 (SPZ's 1/32 step), rotation |q·q'| = 1.0000, SH rest ≤ 0.066 (SPZ's
4–5-bit SH quantisation), DC colour median 0.010; 0.9 % of DC channels lie outside SPZ's representable range and are
clipped (vs 27 % for the classic `.splat` export).
